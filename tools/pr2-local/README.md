Current build: diagnostic v2 + unpaired local controller pilot. Motion is disabled. Automated remote dispatch/results and signed executable updates are blocked pending a supported private connection and trusted signer; do not treat this as an installed connected controller.

Windows 10 x64 portable console package. No installer, admin privilege, service, runner, listener, GitHub token, remote jobs, auto-update, driver replacement, customer input or production app access. Node runtime is bundled by hosted CI. Close Bank Setu before use. Only USB interfaces whose enumerated path contains VID_04B8&PID_0005 may be opened. ## One-time start
1. Download the `PR2-Local-Test-Agent` artifact from the linked successful hosted workflow run for the reviewed commit; extract to a separate folder. Inspect SOURCE.txt and SHA256.json against that run. Checksums detect corruption, not a compromised package; review code/commit provenance before executing.
2. Close Bank Setu, leave the PLQ-20 connected, and double-click Start.cmd. Select the device, confirm `PLQ20 PR2`, then enter `diagnose`. Diagnostics sends the existing ESC n / ESC Z / ESC j / ESC SP B sequence, with no feed, graphics or eject command.
3. Send the displayed diagnostic JSONL file privately in this ChatGPT conversation. Do not post logs publicly. Wait for analysis and a separate agreed hardware test before choosing feed, print or eject.

Each motion action requires typing APPROVE FEED / APPROVE PRINT / APPROVE EJECT locally, applies once, and writes a durable review marker before motion. Print produces only a synthetic rectangle; no bank template or customer record is read. Print does not automatically eject; eject requires a separate run/approval. Use disposable test paper/passbook only. Stop with Ctrl+C; interrupted motion remains uncertain. A stale agent.lock after forced termination requires checking Task Manager that node/helper exited, inspecting the paper, then removing only that lock file in the test directory under LocalAppData. Never delete production files or pending printer jobs blindly.

TX and RX logs include timestamps, raw hex, partial replies/timeouts, strict parser results, paper state and post-action checks. Unknown bytes are preserved and stop motion. No response resynchronization, reset, undocumented status acceptance or automatic retries. The production parser expects exactly ESC r plus one status byte. The prior generic error alone cannot establish whether the cause is response framing, emulation, stale bytes, a device error, or USB driver behavior. Gather bytes before changing the parser. USB read support is driver-dependent; access/read failures are blockers, not evidence of successful printing.

## Diagnostic v2 / controller pilot — 2026-10-21

Epson-authored PLQ-20/PLQ-20M Programming Guide NPD0841-00 Rev A, sheets 73, 76–79 and 83 (https://www.installing.ru/files/plq20pg_e.pdf): ESC Z returns ESC / 7 in PR2; ESC j returns ESC r x. ESC n starts the procedure and has no documented identity response. Therefore the actual repeated 1B 2F 37 is not status and proves neither readiness nor paper presence. Current data cannot distinguish stale/duplicated input, transaction buffering, firmware state or interface behavior. No protocol mode change/reset is attempted.

The isolated helper uses FileStream buffer size 1 instead of 4096 to avoid managed read-ahead. A new bounded capture operation logs entire response windows (256-byte maximum, 1500-ms overall window, 1000-ms first-byte and 150-ms inter-read quiet period), read segment offsets, lengths, timing, cancellation-race bytes and capture limits. Native write acknowledgements and TX logs are distinct from printer acknowledgement. It captures before any command, after control-start, and after each identity/status/paper request; unknown/mixed frames are retained and never skipped into a false ready state. These windows show temporal association, not guaranteed firmware causality. Existing production helper/parser/IPC/Direct Printer Send are untouched. No verified fix to propagate to Direct Printer Send exists until hardware diagnostics establish the cause.

`Controller.cmd` starts a LOCAL QUEUE SECURITY PILOT, not a connected automatic testing service. Remote state is BLOCKED: current Work Mode tools expose repository operations but no authenticated private local-device dispatch/result channel. Plugin discovery did not identify such a supported connection. Public repository issues/files/artifacts are not used for plaintext logs or secrets. No new repository/server was created, no self-hosted runner registered, no credential requested. Installing this package alone cannot remove that blocker.

The controller engine verifies Ed25519-signed exact-schema jobs, 5-minute maximum validity, paired device ID and locally approved bundle pin. Only `diagnose` is enabled. If pairing is absent it exits without opening a printer. Configuration (when a real transport and trusted signer are available) is local `%LOCALAPPDATA%\BankSetu-PR2-Controller\pairing.json`: approvalPublicKey (Ed25519 SPKI PEM), deviceId, bundleHash (SHA256 of packaged SHA256.json).
